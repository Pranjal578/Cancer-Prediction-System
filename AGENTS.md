# Project Operating Instructions

## Mandatory reading order

Before inspecting, changing, testing, or extending this repository, read these files in order:

1. `AGENTS.md`
2. `PRD.md`
3. `PLAN.md`
4. `DESIGN.md`
5. `API.md`
6. `DATABASE.md`
7. `TESTING.md`
8. `MCP.md`

They are the source of truth for the active product scope and current handoff state.

## Active scope

- This is a **breast-cancer-only educational prediction application**.
- It uses the Wisconsin Diagnostic Breast Cancer (WDBC) dataset: 569 records and 30 numeric FNA measurements.
- The only supported outcome is `Benign` or `Malignant`.
- The required models are Logistic Regression, Decision Tree, Random Forest, Support Vector Machine, and K-Nearest Neighbors.
- The application compares all five models and saves the selected model using the selection rule recorded in `PRD.md` and `PLAN.md`.
- The active interface is Streamlit. There is no business REST API and no database.

Do not reintroduce cervical-cancer workflows, XGBoost, SHAP, FastAPI, document parsing, batch triage, audit logging, or patient-history functionality without explicit user approval and a corresponding update to these documents.

## Documentation synchronization rule

For **every** change to source code, configuration, dependencies, data handling, generated artefacts, tests, or runtime behavior:

1. Make the implementation change.
2. Immediately update every affected file among `MCP.md`, `DATABASE.md`, `API.md`, `TESTING.md`, `PLAN.md`, `DESIGN.md`, and `PRD.md`.
3. Add an entry to the `PLAN.md` change log, including the date, change, and verification result.
4. Run the relevant checks in `TESTING.md` and record any changed verification status in `PLAN.md`.

Never leave implementation and these documents out of sync. If no document changes are needed, state why in the handoff or final response.

## Working conventions

- Keep the raw WDBC data unchanged at `cdss/data/raw/wdbc.data`.
- Generated outputs live under `cdss/artifacts/breast/` and are regenerated by `cdss/train_pipeline.py`.
- Use the model pipeline for inference so preprocessing is identical during training and prediction.
- Keep the medical-use disclaimer visible in the Streamlit application and documentation.
- Treat held-out-test performance as an educational benchmark, not clinical validation.
